# Rapid local subtitles (Android 2.5)

The goal is to reduce **finished-file** time in both stages, not just get the first live word sooner. The reported baseline was 18:28.5 of audio, 35:07.5 this attempt (including 25:18.3 in speech and 9:48.3 in translation). Six speech windows came from an earlier attempt. Treat that as a bottleneck report, not a controlled 2.4 benchmark.

## What is now selectable

**Translate → + → On device → Rapid English → Arabic (experimental)** sets manual English, Arabic target, Moonshine Small and Firefox Translations on CPU. Then select **Download models**. No download, language change or engine change happens in previous jobs or simply by opening the sheet. Needs ARM64 Android 9+ and sufficient RAM. Download size is 177,866,044 bytes (142,300,974 speech + 35,565,070 translation), plus the APK and free working space. The existing app-private model folder and external SAF model backup handle these files, too. Library backup/restore still saves video and attached SRTs separately from model weights.

- **Speech:** [Moonshine Voice Android 0.1.6](https://central.sonatype.com/artifact/ai.moonshine/moonshine-voice/0.1.6) with the explicitly pinned [English Small streaming quantization dated 2026-08-21](https://download.moonshine.ai/model/small-streaming-en/quantized_26_08_21/). Kadr uses a fresh stream for each bounded file window, flushes and decodes once, uses completed utterance start/end times (not word timestamps) and retains the overlap/commit boundaries. No microphone, partial decoding, diarization or automatic language claim. Fresh streams sidestep the reused-VAD-history case in [Moonshine #231](https://github.com/moonshine-ai/moonshine/issues/231).
- **Translation:** [Mozilla Firefox Translations English → Arabic v2.2](https://github.com/mozilla/translations) using [Foxlet v0.5.0 / Bergamot / Marian](https://github.com/yinvoke/foxlet-translate/tree/0eff2a15032362115848a496ce1df8ed9fc68650). The specialized INT8 CPU model gets separate inputs in real batches, without LLM prompts, delimiter parsing, neighbouring context or a per-cue client/RPC. Each returned text is applied to the same cue and times; short/invalid batches are not committed. Inference closes between jobs. Stop waits for the current bounded native call, and Resume uses only committed checkpoints.
- **Coverage:** Moonshine here is English-only. Firefox here is English → Arabic only. Both are opt-in and independently selectable: for example, use **Whisper + Firefox** on English that needs more accurate transcription. Use **Whisper + Hy‑MT2** for automatic source, Arabic speech, mixed-language audio or quality-sensitive subtitles. Fast MT does not promise dialect, names or document-level context. Existing manual-source authority and original/translated/bilingual SRT formats stay the same. An English → Arabic job with a saved original transcript can start a separate Firefox or Hy‑MT2 translation without decoding again.
- **No cloud processing in this route.** Only the explicit model downloads go over the network. Each file has an exact expected size and SHA‑256, is verified at installation and reverified before opening a rapid native model. Models are not bundled in the APK; no mutable registry replaces a pin. Moonshine pins are corroborated by [thoughts-local's manifest](https://github.com/jhern254/thoughts-local/pull/68) and [narration-utils' manifest](https://github.com/countrymanprime/narration-utils/pull/307). Firefox pins agree between [Foxlet's registry](https://github.com/yinvoke/foxlet-translate/blob/0eff2a15032362115848a496ce1df8ed9fc68650/registry.json) and [a separate published mirror](https://github.com/slaviboy/VideoSubtitles-translation-models/releases/tag/firefox-bergamot-ar-v1). Upstream model licences: [Moonshine MIT](https://github.com/moonshine-ai/moonshine/blob/v0.1.6/LICENSE), [Mozilla MPL‑2.0](https://github.com/mozilla/firefox-translations-models/blob/main/LICENSE). Native source/licence notices are bundled in `assets/licenses/`.

## Why this path

| Candidate | Evidence and trade-off | Decision |
| --- | --- | --- |
| Whisper Small / Turbo / Vulkan + Hy‑MT2 | Preserves multilingual transcription and translation context. Smaller models or a GPU help sometimes, but still use Whisper decoding and the larger autoregressive translation model. | Keep as quality/coverage options and comparison controls. |
| Moonshine Small EN / Tiny AR | [Moonshine model card](https://github.com/moonshine-ai/moonshine/blob/v0.1.6/docs/models/available-models.md): English Small is 123M, 7.84% OpenASR WER on the **float reference**, not this ARM64 quantized file test. Tiny Arabic is **a separate checkpoint**, with different test material, not bilingual. [An Android offline benchmark](https://github.com/voiceping-ai/android-offline-transcribe) suggests a strong throughput lead for its Moonshine Tiny setup; neither that model nor the phone matches Kadr. | Start with Small for explicit English; keep Arabic and mixed speech on Whisper until separately validated. |
| sherpa-onnx / Zipformer / SenseVoice / Parakeet | [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) is a credible Android runtime. A recognizer's language coverage and timings depend on its model. The compared SenseVoice Small and Parakeet v3 don't cover Arabic speech; long-file quality and cue timing require new tests. | Alternatives if the English Moonshine route misses the local throughput or quality target. |
| Dedicated text engines: Firefox, ML Kit, OPUS-MT | [Foxlet's Android measurements](https://github.com/yinvoke/foxlet-translate/blob/v0.5.0/benchmark/data/v0.5.0/derived/README.en.md) on Xiaomi 14 report 101 warm EN→Chinese inputs/s with one worker (vs 14.6 ML Kit in that test). Those are different languages/inputs, not Kadr EN→Arabic or a Hy‑MT2 speedup. [ML Kit text MT](https://developers.google.com/ml-kit/language/translation/android) is also lightweight and device-local, but adds [Google attribution and metrics obligations](https://developers.google.com/ml-kit/language/translation/translation-terms). OPUS-MT/Marian ONNX would require a separate tokenizer and decoder integration. | Use the small, direct Mozilla EN→AR pack with the ARM native batch API. |
| Direct GenAI speech translation | [Google's speech translation API](https://developers.google.com/ml-kit/genai/speech-translation/android) is an alpha with chipset/OS and service dependencies. The example returns text/locale; it does not establish Arabic support and subtitle-aligned time codes for this use case. Whisper translate targets English, not Arabic. | Not a substitute for generating both the original and Arabic timed SRTs. |

## Measure on the target phone

1. Use a saved MP4 or audio file (not an HLS/DASH playlist). Start with **the same 2–4 minute English clip**, then run the long clip to check sustained speed and heat. Install all weights first; enable airplane mode if desired. Don't measure downloads or Resume as a fresh run.
2. Hold manual **English → Arabic** fixed. Compare fresh jobs using (A) the existing Whisper + Hy‑MT2 setting, (B) Moonshine + Hy‑MT2, and (C) Moonshine + Firefox. To isolate MT on identical input text and timings, also use **Translate saved transcript with Firefox** on an English → Arabic job and compare the MT stage only. That job intentionally skips ASR.
3. On each job, open **Performance** and record audio length, actual CPU/GPU, both stage times, reused counts, and total elapsed through SRT publication. Record the phone/OS, cool off between runs, and repeat for consistency. First-batch time alone doesn't establish total throughput. Preserve the SRTs from each run for review; the library displays the most recently attached version for a language.
4. Compare names, numbers, missing words, and cue lead/lag near the window seams; review translation meaning in context. Include a difficult clip and an Arabic/mixed clip on the existing route before using Rapid for important work.

The local pipeline tests mock both new native inference calls to prove routing, checkpointing, alignment and cancellation. They do not establish the real engines' transcript/translation quality or a phone speed multiplier.
